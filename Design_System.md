# Design System

## Purpose

This document defines the visual language of the portfolio.

It ensures that every component follows the same design principles and prevents inconsistencies as the project grows.

Whenever a new section or component is added, it should conform to this design system.

---

# Design Principles

The design should feel:

- Calm
- Minimal
- Editorial
- Premium
- Timeless
- Intentional
- Highly readable

The portfolio should resemble a carefully crafted personal website rather than a generic developer portfolio.

Visual restraint is preferred over decoration.

---

# Inspiration

The visual style should draw inspiration from products and websites such as:

- Apple
- Linear
- Vercel
- Stripe Documentation
- Notion
- Raycast
- Modern editorial websites

The emphasis is on clarity, spacing, and typography.

---

# Layout

## Content Width

Use a consistent maximum width throughout the website.

Recommended:

1200px-1280px

Avoid sections with inconsistent widths.

---

## Section Spacing

Every major section should breathe.

Use generous vertical spacing.

Desktop:

120px-160px

Tablet:

96px-120px

Mobile:

64px-80px

Never allow sections to feel cramped.

---

## Grid

Desktop:

Two-column layouts where appropriate.

Mobile:

Single-column layouts.

Content should naturally reflow.

---

# Typography

Typography is one of the most important parts of this website.

Hierarchy should be obvious.

Recommended scale:

Hero Heading

56-72px

Section Heading

36-48px

Subheading

20-24px

Body

16-18px

Caption

14px

Line height should prioritize readability.

Paragraph width should remain comfortable.

Avoid extremely long lines.

---

# Color Philosophy

Use a restrained color palette.

The interface should rely primarily on:

- background
- typography
- whitespace

Accent colors should only be used to draw attention where necessary.

Never allow accent colors to dominate the page.

---

# Cards

Cards should feel premium.

Characteristics:

- generous padding
- subtle borders
- soft hover effects
- consistent border radius
- minimal shadows

Avoid excessive elevation.

Cards should appear calm.

---

# Buttons

Buttons should have only a few variants.

Primary

Secondary

Ghost

Destructive (only if ever required)

Button styles should remain consistent throughout the website.

---

# Icons

Icons should be:

simple

minimal

consistent

Avoid decorative icon packs.

Icons should support content rather than dominate it.

---

# Images

Images should feel authentic.

Preferred:

- personal photography
- product screenshots
- realistic workspace images

Avoid:

- generic stock developer photos
- artificial AI artwork
- decorative filler images

Project screenshots should be clear and meaningful.

---

# Components

Every component should follow the same visual language.

Core reusable components include:

Section

Container

Button

Card

Badge

Tag

Project Card

Timeline Item

Book Card

Article Card

Technology Chip

Interest Card

Divider

Section Heading

Components should be composable and reusable.

---

# Project Cards

Every project card should communicate:

Problem

Approach

Outcome

Technologies

Actions

Images should be visually dominant.

Technology chips should remain secondary.

Projects should feel like product case studies rather than GitHub repositories.

---

# Timeline

The Journey section should use a reusable timeline component.

Each milestone contains:

Title

Description

Optional year

Optional icon

Timeline animations should be subtle.

---

# Technology Chips

Technology chips should:

be small

be understated

have consistent sizing

never dominate a section

Technologies support the story rather than becoming the story.

---

# Reading Cards

Reading cards should include:

Book cover

Title

Author

Short takeaway

Optional reading progress

They should remain compact.

---

# Article Cards

Article cards should include:

Category

Title

Preview

Date

Reading Time

The layout should encourage future expansion.

---

# Hover States

Hover interactions should feel refined.

Recommended:

- slight elevation
- border color transition
- subtle background shift
- image zoom (very subtle)

Avoid exaggerated movement.

---

# Animations

Animations should support storytelling.

Preferred:

Fade

Slide

Reveal

Stagger

Timeline reveal

Image reveal

Avoid:

Bounce

Large scaling

Spinning

Overly playful motion

Animations should never distract from the content.

---

# Motion Timing

Animations should feel smooth.

Use consistent durations.

Recommended:

150ms-300ms

Longer animations should be used sparingly.

---

# Border Radius

Maintain a consistent radius throughout the project.

Cards

Buttons

Inputs

Images

Badges

should all belong to the same visual family.

---

# Shadows

Use minimal shadows.

Prefer borders and spacing over heavy elevation.

Shadows should communicate depth, not decoration.

---

# Empty Space

Whitespace is part of the design.

Never fill empty areas simply because space exists.

Whitespace improves readability and creates visual rhythm.

---

# Accessibility

Maintain sufficient contrast.

Support keyboard navigation.

Respect prefers-reduced-motion.

Ensure interactive elements have visible focus states.

All images should have descriptive alt text.

---

# Responsive Design

Every component must be responsive.

Desktop should never simply shrink into mobile.

Layouts should adapt intentionally.

Typography should scale gracefully.

Cards should stack naturally.

Spacing should remain consistent across breakpoints.

---

# Visual Consistency Rules

Before introducing any new component, ask:

- Does it match the existing visual language?
- Does it improve readability?
- Does it maintain consistency?
- Is it reusable?
- Does it support the story being told?

If the answer is no, redesign the component rather than forcing it into the interface.

---

# Final Principle

The design should disappear behind the content.

Visitors should remember:

the ideas,

the projects,

the journey,

and the thinking,

not flashy UI effects.

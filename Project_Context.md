# Portfolio Website V2 - Project Context

## Purpose

This project is not a complete redesign of my existing portfolio.

It is a thoughtful evolution of a portfolio I built over two years ago.

The goal is to create a website that accurately represents who I am today, how I think, what I value, and the type of problems I enjoy solving.

The portfolio should communicate far more than technical skills.

It should communicate curiosity, craftsmanship, entrepreneurship, continuous learning, thoughtful engineering, and product thinking.

---

# Core Philosophy

The portfolio should answer one question:

> "Who is this person?"

rather than

> "What technologies does he know?"

Projects exist as evidence of my thinking.

Technologies exist as supporting tools.

Everything on the website should reinforce this philosophy.

---

# Identity

The portfolio should communicate that I am:

- a lifelong learner
- an entrepreneurial software engineer
- passionate about Artificial Intelligence
- especially interested in Natural Language Processing
- someone who enjoys understanding problems deeply before building solutions
- someone who enjoys reading
- someone who enjoys writing
- someone interested in theology
- someone interested in philosophy
- someone who enjoys building products rather than simply writing software

---

# Design Philosophy

The visual design should feel:

- calm
- modern
- premium
- editorial
- minimal
- timeless

Avoid designs that feel trendy.

Avoid making the portfolio resemble stereotypical AI developer portfolios.

Do NOT introduce:

- particle backgrounds
- glowing gradients everywhere
- cyberpunk effects
- excessive glassmorphism
- unnecessary animations

The interface should feel refined rather than flashy.

---

# Visual Reference

The provided UI mockup is the primary visual reference.

It should be treated as inspiration for:

- layout
- spacing
- hierarchy
- visual rhythm
- section arrangement
- card design

The content shown inside the mockup is placeholder content.

Do NOT reuse the text.

---

# Development Philosophy

This project should be developed incrementally.

Never attempt to redesign or rewrite the entire website in one step.

Each section should be completed, reviewed, refined, and approved before moving to the next.

The preferred workflow is:

Research

->

Planning

->

Implementation

->

Review

->

Refinement

->

Next section

---

# Development Order

Always work in the following order unless instructed otherwise.

1. Project setup
2. Global design system
3. Layout
4. Navigation
5. Hero
6. Journey
7. Projects
8. Experience
9. What I Build
10. Technologies
11. Currently Learning
12. Currently Reading
13. Writing
14. Beyond Software
15. Contact
16. Animations
17. Responsive improvements
18. Accessibility
19. Performance
20. Final polish

Never jump ahead.

---

# Design System

The project should use a consistent design language.

Maintain consistency in:

- spacing
- typography
- corner radius
- shadows
- card styling
- button styling
- iconography
- animation timing
- colors

Avoid introducing one-off styles.

---

# Component Philosophy

Every section should be implemented using reusable components.

Examples include:

Section wrapper

Container

Button

Card

Timeline

Project card

Technology chip

Book card

Article card

Tag

Badge

Image component

Avoid duplicated layouts.

Favor composition.

---

# Content Philosophy

Content is more important than decoration.

Every section should communicate something meaningful.

Avoid placeholder marketing language.

Avoid generic portfolio wording.

The tone should be:

thoughtful

clear

confident

curious

Never exaggerate.

Never use buzzwords simply because they sound impressive.

---

# Project Philosophy

Projects are not repositories.

Projects are stories.

Every featured project should answer:

What problem existed?

Why did it matter?

What approach was taken?

What was learned?

What was the outcome?

Technology lists should always be secondary.

---

# Skills Philosophy

Avoid traditional skills sections.

Do not use:

progress bars

skill percentages

large technology logo walls

Instead communicate:

What I Build

followed by

Technologies I Use

---

# Animation Philosophy

Animations should support storytelling.

Good animations include:

fade

slide

stagger

timeline reveal

image reveal

Avoid decorative animations.

The interface should remain calm.

---

# Accessibility

Accessibility is required.

Use:

semantic HTML

keyboard navigation

descriptive alt text

accessible contrast

focus states

respect prefers-reduced-motion

---

# Responsiveness

Desktop is the primary experience.

Tablet should adapt naturally.

Mobile should preserve hierarchy.

Do not simply shrink desktop layouts.

Layouts should reflow intelligently.

---

# Code Quality

All code should be production quality.

Requirements:

- reusable components
- clean architecture
- TypeScript
- maintainability
- scalability
- readable code
- descriptive naming
- minimal duplication

Prefer composition over repetition.

---

# AI Working Rules

When implementing changes:

1. Understand the purpose of the section.

2. Plan before coding.

3. Explain significant architectural decisions.

4. Preserve consistency.

5. Do not redesign unrelated components.

6. Avoid introducing unnecessary dependencies.

7. Prioritize maintainability.

8. Ask for clarification whenever requirements conflict.

---

# Success Criteria

The project is successful if visitors leave thinking:

"This is someone who genuinely enjoys understanding difficult problems, learns continuously, and builds thoughtful products."

rather than

"This is another software engineer portfolio."

The portfolio should feel personal, timeless, intentional, and authentic.

Everything added to the project should support that goal.
